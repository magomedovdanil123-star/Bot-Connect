Этап 2 — модуль генерации изображений

Продолжай разработку существующего проекта AI Content Factory. Не переписывай уже работающий функционал и не ломай текущие API, Telegram-бота, базу данных и веб-интерфейс.

Цель этапа

Добавить полноценный модуль генерации изображений для создаваемого контента.

Пользователь после создания сценария должен иметь возможность автоматически получить набор изображений/кадров, подходящих под сценарий.

⸻

1. Интерфейс

В существующем веб-интерфейсе добавь новый этап:

Сценарий → Изображения → Видео

После генерации сценария показать кнопку:

🎨 Создать изображения

Добавить настройки:

* количество изображений;
* формат изображения:
    * 9:16 — Shorts / Reels / TikTok;
    * 16:9 — YouTube;
    * 1:1 — пост;
* визуальный стиль;
* степень реализма;
* наличие людей;
* цветовая атмосфера;
* единый персонаж между сценами.

По умолчанию:

* формат: 9:16;
* стиль: cinematic realistic;
* реализм: высокий;
* изображения должны соответствовать сценарию.

⸻

2. Автоматическое создание промптов

Не заставляй пользователя вручную писать промпт для каждого изображения.

AI должен взять готовый сценарий и автоматически разделить его на сцены.

Например:

Сцена 1:
«Курьер получает необычный заказ поздним вечером».

AI должен сформировать подробный image prompt:

* главный объект;
* персонажи;
* действие;
* окружение;
* время суток;
* освещение;
* камера;
* композиция;
* эмоции;
* стиль;
* соотношение сторон;
* важные детали.

Промпты должны быть максимально конкретными и пригодными для генерации изображения.

⸻

3. Важное требование — визуальная последовательность

Если в сценарии присутствует один главный персонаж, изображения должны сохранять его внешний вид.

Создай сущность:

CharacterProfile

В ней хранить:

* пол;
* возраст;
* внешность;
* волосы;
* одежду;
* аксессуары;
* особенности лица;
* стиль;
* дополнительные постоянные признаки.

При генерации следующих сцен автоматически добавлять описание персонажа в prompt.

Цель:

один персонаж должен выглядеть одинаково во всех сценах.

⸻

4. Архитектура

Создай отдельный модуль:

image_generation

Пример структуры:

image_generation/
├── __init__.py
├── service.py
├── prompt_builder.py
├── scene_analyzer.py
├── providers/
│   ├── base.py
│   └── ...
├── models.py
└── schemas.py

Не привязывай бизнес-логику напрямую к одному провайдеру.

Используй интерфейс:

class ImageProvider:
    async def generate(self, prompt, settings):
        ...

Чтобы в будущем можно было легко заменить API генерации изображений.

⸻

5. API

Добавь API endpoints примерно такого типа:

POST /api/projects/{project_id}/images/generate
GET  /api/projects/{project_id}/images
GET  /api/images/{image_id}
DELETE /api/images/{image_id}
POST /api/images/{image_id}/regenerate

Генерация должна быть асинхронной.

Не блокируй HTTP request на время генерации.

Используй существующую архитектуру проекта.

Статусы:

pending
processing
completed
failed

⸻

6. База данных

Добавь таблицу для изображений.

Например:

generated_images

Поля:

id
project_id
scene_id
prompt
negative_prompt
provider
model
aspect_ratio
status
image_url
storage_path
width
height
generation_time
error
created_at
updated_at

Если в проекте уже есть таблица сцен — используй существующую связь.

Не создавай дублирующие сущности.

⸻

7. Negative Prompt

Автоматически формируй negative prompt для фотореалистичных сцен.

Учитывай:

* blurry;
* low quality;
* distorted face;
* deformed hands;
* extra fingers;
* duplicate people;
* bad anatomy;
* text;
* watermark;
* logo;
* oversaturated;
* artificial appearance.

При этом не добавляй ограничения, которые могут ухудшить конкретный стиль изображения.

⸻

8. Генерация нескольких сцен

Если сценарий содержит 10 сцен, пользователь должен увидеть:

Генерация изображений
Сцена 1   ✅
Сцена 2   ✅
Сцена 3   ⏳
Сцена 4   ⏳
...

Покажи общий прогресс:

3 / 10

После завершения:

Все изображения готовы ✅

⸻

9. Карточка изображения

Для каждого изображения показать:

* preview;
* номер сцены;
* описание сцены;
* использованный prompt;
* статус;
* время генерации.

Кнопки:

🔄 Перегенерировать

✏️ Изменить prompt

⬇️ Скачать

🗑️ Удалить

⸻

10. Ручное редактирование prompt

Пользователь должен иметь возможность открыть изображение и изменить prompt.

Например:

Prompt:
Молодой курьер в желтой куртке стоит возле подъезда...

Кнопка:

🔄 Перегенерировать

После этого новая версия не должна уничтожать старую.

Сохраняй историю генераций.

⸻

11. Версии

Создай связь:

scene
  └── image
       ├── version 1
       ├── version 2
       └── version 3

Пользователь может выбрать нужную версию как основную.

⸻

12. Обработка ошибок

Если API генерации изображения недоступен:

* статус failed;
* сохранить ошибку;
* показать пользователю понятное сообщение;
* дать кнопку повторной генерации.

Одна ошибка сцены не должна останавливать генерацию остальных сцен.

⸻

13. Безопасность

API-ключи не должны попадать:

* во frontend;
* в Git;
* в database;
* в логи.

Используй environment variables.

Например:

IMAGE_API_KEY
IMAGE_PROVIDER
IMAGE_MODEL

Не хардкодь ключи.

⸻

14. Интеграция с существующим проектом

Перед внесением изменений:

1. Проанализируй текущую структуру проекта.
2. Найди существующие модели Project / Scene / Script.
3. Найди существующий API.
4. Найди систему авторизации.
5. Найди текущую систему хранения файлов.
6. Найди существующую систему очередей/background jobs.
7. Используй уже существующие решения вместо создания дублей.

Не переписывай существующий backend.

Не меняй работающие endpoints без необходимости.

⸻

17. Что НЕ делать

Не добавляй сейчас:

* генерацию видео;
* монтаж;
* озвучку;
* публикацию;
* сложную систему оплаты;
* новые сторонние сервисы без необходимости.

Это следующий этап.

Сейчас задача только:

Сценарий → сцены → AI prompts → изображения → сохранение → просмотр → перегенерация.
