Этап 3 — полноценный модуль AI-озвучки

Продолжай разработку существующего AI Content Factory.

Не переписывай существующий функционал.

На предыдущем этапе уже реализована генерация сценария и изображений.

Сейчас реализуй отдельный полноценный модуль:

Сценарий → AI Voice → готовый аудиофайл

Пока НЕ реализовывай музыку и финальный монтаж видео. Это будут следующие этапы.

2. Архитектура

Создай отдельный модуль:

audio_generation/
├── __init__.py
├── service.py
├── text_processor.py
├── voice_settings.py
├── schemas.py
├── models.py
└── providers/
    ├── base.py
    └── ...

Используй provider abstraction.

class TTSProvider:
    async def generate(
        self,
        text: str,
        voice: str,
        settings: dict
    ):
        ...

Бизнес-логика не должна напрямую зависеть от конкретного API.

⸻

3. Провайдер

Перед реализацией:

1. Проанализируй доступные API/SDK в текущем проекте.
2. Если уже подключён TTS provider — используй его.
3. Если TTS ещё не подключён — реализуй интеграцию через environment variables.
4. Не хардкодь API-ключи.

Создай настройки:

TTS_PROVIDER
TTS_API_KEY
TTS_MODEL

Если конкретный provider требует дополнительные параметры — вынеси их в environment variables.

⸻

4. Обработка сценария

Не отправляй огромный сценарий в TTS одним неструктурированным текстом.

Сначала обработай сценарий.

Нужно сохранить:

* текст;
* предложения;
* абзацы;
* паузы;
* сцены.

Например:

Scene 1
Текст...
Scene 2
Текст...
Scene 3
Текст...

Для каждой сцены сохранить аудио duration.

⸻

5. Паузы

Добавь автоматические паузы.

Например:

.

обычная пауза.

...

более длинная пауза.

Между сценами:

scene_pause = 300–700 ms

Но не добавляй паузы механически после каждого предложения.

Цель — естественная речь.

⸻

6. Эмоциональная озвучка

Для каждого блока текста AI должен определить подходящую манеру речи.

Например:

Интрига:
эмоциональность +20%
Факт:
нейтрально
Напряжённый момент:
эмоциональность +40%
Финал:
уверенная подача

Если выбранный TTS provider не поддерживает emotion controls, реализуй максимально близкое поведение через настройки/SSML, если provider это позволяет.

Не выдумывай неподдерживаемые параметры API.

⸻

7. SSML

Если выбранный provider поддерживает SSML:

используй его для:

* пауз;
* ударений;
* скорости;
* интонации.

Но сделай fallback на обычный text input, если SSML недоступен.

⸻

9. Формат аудио

Финальный аудиофайл:

WAV или MP3
44.1 kHz
stereo

Если provider возвращает другой формат — корректно конвертируй.

Для последующего FFmpeg-монтажа аудио должно быть гарантированно читаемым.

⸻

10. Сегменты

Очень важно сохранить отдельные сегменты.

Например:

voice/
├── scene_001.mp3
├── scene_002.mp3
├── scene_003.mp3
└── full_voice.mp3

Это понадобится для синхронизации изображения и видео.

⸻

13. Перегенерация

Пользователь должен иметь возможность:

* поменять голос;
* поменять скорость;
* поменять стиль;
* поменять эмоциональность;

и повторно создать озвучку.

Старую версию не удалять.

Хранить версии:

Voice v1
Voice v2
Voice v3

Пользователь выбирает активную версию.

⸻

14. API

Добавь:

POST /api/projects/{project_id}/voice/generate
GET /api/projects/{project_id}/voice
GET /api/voice/{voice_id}
GET /api/voice/{voice_id}/status
POST /api/voice/{voice_id}/regenerate
POST /api/voice/{voice_id}/activate
DELETE /api/voice/{voice_id}

Генерация должна выполняться background job.

HTTP request не должен зависать на время генерации.
