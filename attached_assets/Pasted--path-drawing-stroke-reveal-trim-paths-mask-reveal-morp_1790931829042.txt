— path drawing;
— stroke reveal;
— trim paths;
— mask reveal;
— morphing;
— stagger;
— spring;
— overshoot;
— opacity;
— scale;
— animated masks;
— line propagation;
— particle movement;
— pulse;
— animated counters;
— parallax;
— camera drift;
— object transformation.

============================================================
14. ОБЪЕКТЫ НЕ ПОЯВЛЯЮТСЯ — ОНИ СТРОЯТСЯ
============================================================

Главный принцип анимации:

НЕ:
объект просто появился.

А:
объект сформировался.

Линия:
прорисовывается.

График:
строится.

Сеть:
соединяется.

Узел:
формируется слоями.

Диаграмма:
собирается.

Текст:
раскрывается маской.

Данные:
движутся.

Система:
реагирует.

============================================================
15. ПРИЧИННО-СЛЕДСТВЕННАЯ АНИМАЦИЯ
============================================================

Одно движение должно вызывать другое.

Например:

точка активируется
↓
из неё выходит линия
↓
линия достигает узла
↓
узел реагирует
↓
возникает импульс
↓
следующий объект меняется
↓
появляется результат.

Это создаёт визуальное повествование.

Не запускай набор несвязанных анимаций одновременно.

============================================================
16. МИКРОАНИМАЦИИ
============================================================

После построения сцена не должна становиться абсолютно статичной.

Добавляй очень тонкие:

— pulses;
— moving particles;
— flowing data;
— tiny indicators;
— breathing glow;
— parallax;
— graph movement;
— marker movement;
— background drift.

Микроанимация должна быть едва заметной.

============================================================
17. MOTION CURVES
============================================================

Избегай линейного движения.

Используй естественные easing curves:

easeOutCubic
easeInOutCubic
easeOutQuart
easeInOutQuart

При необходимости:

spring
overshoot

Движение должно иметь:

ускорение
→ движение
→ естественное торможение.

============================================================
18. КИНЕМАТОГРАФИЧЕСКОЕ ДВИЖЕНИЕ
============================================================

Допускается очень слабое движение виртуальной камеры:

— slow push-in;
— slow pull-out;
— horizontal drift;
— parallax;
— controlled reframing.

Амплитуда маленькая.

Камера не должна отвлекать.

Она должна создавать ощущение глубины.

============================================================
19. ПЕРЕХОДЫ
============================================================

Сцены НЕ должны ощущаться отдельными слайдами.

НЕ используй постоянно:

fade out
→ пустота
→ fade in.

Предпочитай:

MATCH CUT
MORPH
CONTINUOUS PATH
OBJECT TRANSFORMATION
MASK TRANSITION
CAMERA TRANSITION

Элемент сцены A должен становиться частью сцены B.

Например:

точка → узел;
узел → диаграмма;
линия → график;
график → контур;
круг → масштабируется в следующую систему;
частица → становится новым объектом.

Создавай ОДИН НЕПРЕРЫВНЫЙ ВИЗУАЛЬНЫЙ ПОТОК.

============================================================
20. ТАЙМИНГ
============================================================

Ориентировочная структура сцены:

0.0–0.4 сек
визуальный триггер

0.4–1.1 сек
построение основной структуры

1.1–1.8 сек
вторичные элементы

1.8–2.5 сек
главное действие

2.5–3.0 сек
смысловой акцент / текст

3.0–3.5 сек
микродвижение + начало перехода

Не воспринимай эти цифры как жёсткий шаблон.

Ритм должен зависеть от содержания и озвучки.

============================================================
21. СИНХРОНИЗАЦИЯ С ОЗВУЧКОЙ
============================================================

Если присутствует voice-over:

анимация должна следовать СМЫСЛУ речи.

Не показывай результат раньше, чем о нём говорится.

Ключевые визуальные события должны совпадать с:

— важными словами;
— числами;
— изменениями мысли;
— причинно-следственными связями;
— паузами.

Визуальный ряд должен усиливать narration.

============================================================
22. ДАННЫЕ И ЦИФРЫ
============================================================

Если в тексте присутствуют числа, проценты или финансовые показатели,
не ограничивайся выводом цифры на экран.

Используй визуализацию:

— изменение масштаба;
— сравнение;
— движение;
— заполнение;
— распределение;
— график;
— отношение;
— прогресс;
— поток.

Цифра + визуальная метафора работают вместе.

============================================================
23. GLOW
============================================================

Glow использовать только как тонкий акцент.

Он должен быть:

— мягким;
— локальным;
— слабым;
— контролируемым.

Не превращать стиль в:

NEON
CYBERPUNK
GAMING UI.

============================================================
24. ВИЗУАЛЬНЫЙ РИТМ
============================================================

Не делай каждую сцену одинаково интенсивной.

Чередуй:

сложная сцена
→ спокойная сцена
→ динамичная сцена
→ визуальная пауза
→ кульминация.

Видео должно «дышать».

============================================================
25. НЕ ПОВТОРЯЙ КОМПОЗИЦИИ
============================================================

Единый стиль НЕ означает одинаковые сцены.

Не повторяй постоянно:

— одну схему;
— одинаковые круги;
— одинаковые линии;
— одинаковую сетку;
— одинаковое расположение текста;
— одинаковый переход.

Сохраняй ДНК дизайна,
но меняй визуальные решения.

============================================================
26. ТЕХНИЧЕСКОЕ КАЧЕСТВО
============================================================

Цель:

60 FPS.

Все:

— линии;
— окружности;
— соединения;
— маски;
— траектории;
— текст;
— отступы

должны быть визуально точными.

Используй единую геометрическую сетку.

Никаких случайных координат и кривых соединений.

============================================================
27. НЕ ЭКОНОМЬ НА КОДЕ
============================================================

КРИТИЧЕСКОЕ ПРАВИЛО.

Не оптимизируй визуал ради минимального количества кода.

Если качественная сцена требует:

5 элементов → используй 5.

30 элементов → используй 30.

100 элементов → используй 100.

Если нужны:

— дополнительные SVG paths;
— masks;
— particles;
— gradients;
— multiple layers;
— custom easing;
— сложный timeline;

используй их.

При конфликте:

ПРОСТОТА КОДА
VS
ВИЗУАЛЬНОЕ КАЧЕСТВО

ВСЕГДА ПОБЕЖДАЕТ ВИЗУАЛЬНОЕ КАЧЕСТВО.

============================================================
28. НЕ ЭКОНОМЬ НА АНИМАЦИИ
============================================================

Не заменяй полноценную последовательность одним эффектом.

ПЛОХО:

opacity 0 → 1.

ХОРОШО:

точка
→ импульс
→ линия
→ структура
→ данные
→ реакция
→ смысловой акцент
→ переход.

============================================================
29. ЗАПРЕЩЁННЫЙ СТИЛЬ
============================================================

КАТЕГОРИЧЕСКИ НЕ ДЕЛАЙ:

— PowerPoint animation;
— обычную презентацию;
— dashboard;
— SaaS landing page;
— mobile UI;
— набор карточек;
— glassmorphism;
— generic infographic;
— generic AI art;
— stock illustration;
— clipart;
— cartoon;
— дешёвый cyberpunk;
— excessive neon;
— стандартные SVG icons;
— белый фон;
— огромные градиенты;
— случайные цвета.

============================================================
30. ЗАПРЕЩЁННАЯ ПРИМИТИВНОСТЬ
============================================================

НЕ СЧИТАЙ полноценной сценой:

кружок + линия + текст.

НЕ СЧИТАЙ полноценной сценой:

иконка + заголовок.

НЕ СЧИТАЙ полноценной сценой:

стрелка + цифра.

НЕ СЧИТАЙ полноценной сценой:

график + fade-in.

Если сцену можно собрать за несколько минут из базовых фигур,
она НЕДОСТАТОЧНО ПРОРАБОТАНА.

============================================================
31. QUALITY GATE
============================================================

Перед финальным рендером каждой сцены проведи внутреннюю проверку.

ПРОВЕРКА №1 — СМЫСЛ

Понятен ли смысл без длинного текста?

ПРОВЕРКА №2 — КОМПОЗИЦИЯ

Есть ли один очевидный центр внимания?

ПРОВЕРКА №3 — ДЕТАЛИ

Есть ли достаточное количество качественных микродеталей?

ПРОВЕРКА №4 — ГЛУБИНА

Есть ли background / midground / foreground?

ПРОВЕРКА №5 — MOTION

Есть ли минимум несколько связанных этапов анимации?

ПРОВЕРКА №6 — ПРИЧИННОСТЬ
