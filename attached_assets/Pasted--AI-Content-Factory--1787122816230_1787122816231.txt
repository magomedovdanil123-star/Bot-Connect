Создай первый модуль моего проекта — AI Content Factory.

ВАЖНО: сейчас реализуй ТОЛЬКО первый этап. Не добавляй генерацию изображений, озвучку, видео, FFmpeg и публикацию. Мы будем подключать эти модули поэтапно.

Цель

Мне нужен бот/веб-интерфейс, в котором я ввожу тему будущего короткого ролика, а AI через OpenRouter автоматически создаёт полноценный сценарий.

Пример ввода:

«Курьер приехал на обычный заказ, но клиент попросил его сделать кое-что странное»

AI должен превратить это в интересную историю для Shorts / Reels / TikTok.

1. OpenRouter

Используй OpenRouter API.

API-ключ НЕ прописывать непосредственно в коде.

Использовать переменную окружения:

OPENROUTER_API_KEY

Сделай отдельный конфигурационный модуль для API.

Модель пока вынеси в переменную:

OPENROUTER_MODEL

Если переменная не задана, используй подходящую недорогую модель OpenRouter для генерации текста.

Сделай нормальную обработку ошибок API:

* отсутствует API key;
* ошибка соединения;
* ошибка API;
* пустой ответ;
* превышение лимита.

Никогда не показывай API-ключ пользователю.

2. Интерфейс

Создай простой удобный интерфейс AI Content Factory.

На главной странице:

AI CONTENT FACTORY

Поле:

«О чём будет ролик?»

Большое textarea.

Дополнительные настройки:

* Формат: Shorts / Reels / TikTok
* Длительность: 30 / 60 / 90 секунд
* Стиль: реалистичная история / драматичная / смешная / жизненная / криминальная / мотивационная
* Тон: серьёзный / эмоциональный / дерзкий / интригующий

Кнопка:

«🚀 СОЗДАТЬ СЦЕНАРИЙ»

После нажатия показать состояние:

«🧠 Пишу сценарий…»

3. Системный промпт сценариста

Создай отдельный системный prompt для AI-сценариста.

AI должен выступать как профессиональный сценарист коротких вертикальных видео.

Главная задача — удержание внимания.

Структура каждого сценария:

1. HOOK — первые 1–3 секунды.
2. Завязка.
3. Развитие истории.
4. Неожиданный поворот или усиление интриги.
5. Кульминация.
6. Финал.
7. CTA, если он уместен.

Не писать скучные вступления вроде:
«Сегодня я расскажу вам историю…»

Не использовать воду.

Каждая сцена должна двигать историю вперёд.

Текст должен звучать естественно при озвучке человеком или AI.

Писать разговорным языком.

Сценарий должен соответствовать выбранной длительности.

4. Сценарий должен возвращаться в JSON

Очень важно: AI должен возвращать строго структурированный JSON.

Используй примерно такую структуру:

{
“title”: “Название ролика”,
“hook”: “Сильный hook”,
“description”: “Краткое описание”,
“duration_seconds”: 60,
“scenes”: [
{
“scene_number”: 1,
“duration_seconds”: 5,
“voice_text”: “Текст для озвучки”,
“visual_description”: “Что должно происходить в этой сцене”,
“image_prompt”: “Подробный prompt для будущей генерации изображения”
}
],
“ending”: “Финальная фраза”,
“cta”: “Призыв к действию”
}

Количество сцен AI определяет самостоятельно в зависимости от длительности.

Для 60-секундного ролика желательно примерно 7–12 сцен.

5. Очень важно — готовить данные для будущих модулей

Мы позже будем подключать:

Сценарий
↓
Озвучка
↓
Генерация изображений
↓
Видео

Поэтому уже сейчас каждая сцена должна иметь:

voice_text

и отдельно:

image_prompt

Это принципиально важно.

Например:

voice_text:
«Я уже собирался заканчивать смену, когда пришёл последний заказ.»

image_prompt:
«Realistic cinematic Moscow evening, Yandex-style food courier standing beside his bicycle, looking at his smartphone, apartment buildings in background, natural lighting, documentary photography, vertical 9:16»

В будущем image_prompt будет автоматически отправляться в API генерации изображений.

6. Проверка результата

После получения JSON приложение должно проверить:

* JSON валидный;
* есть title;
* есть hook;
* есть scenes;
* у каждой сцены есть voice_text;
* у каждой сцены есть visual_description;
* у каждой сцены есть image_prompt;
* duration_seconds соответствует выбранной длительности.

Если AI вернул некорректный JSON — автоматически выполнить повторный запрос с просьбой исправить формат.

Не показывать пользователю технические ошибки JSON.
