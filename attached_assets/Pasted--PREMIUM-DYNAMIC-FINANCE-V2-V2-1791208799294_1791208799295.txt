ФИНАЛЬНАЯ ПОЛИРОВКА PREMIUM DYNAMIC FINANCE V2

Мы уже получили очень хороший результат в текущем V2 Cinematic Documentary тесте.

ВАЖНО:
Это НЕ новый renderer с нуля.
Это ФИНАЛЬНАЯ ПОЛИРОВКА текущего V2.

НЕ переписывай архитектуру.
НЕ возвращай старый Finance Long V4.
НЕ убирай существующие визуальные сцены.
НЕ убирай реальные архивные материалы.
НЕ убирай charts.
НЕ убирай market cap.
НЕ убирай comparison.
НЕ убирай current cinematic style.
НЕ подключай Telegram production до завершения теста.

Нужно сохранить примерно 90% текущего V2 и улучшить оставшиеся 10%.

Главная проблема текущего теста:

ВИЗУАЛЫ УЖЕ ХОРОШИЕ.

Но СУБТИТРЫ СЕЙЧАС НЕ ЯВЛЯЮТСЯ ЧАСТЬЮ КИНЕМАТОГРАФИЧЕСКОГО МОНТАЖА.

Именно это сейчас нужно исправить.

==================================================
1. ГЛАВНАЯ ЗАДАЧА — ВЕРНУТЬ НАСТОЯЩИЕ КИНЕТИЧЕСКИЕ СУБТИТРЫ
==================================================

Нам нужны не подписи:

"ЭТО ИСТОРИЧЕСКАЯ"
"СМОТРИМ НА ЗНАЧЕНИЕ"
"СООБЩЕСТВО"

Такие подписи выглядят как UI label.

Они НЕ являются полноценными субтитрами.

Нужно вернуть настоящий subtitle engine.

Каждая произнесённая фраза должна быть синхронизирована с voice.

Например диктор говорит:

"Dogecoin появился в 2013 году как шутка, но затем превратился в один из самых узнаваемых криптопроектов."

На экране должно быть примерно:

DOGECOIN ПОЯВИЛСЯ
В 2013 ГОДУ

затем:

КАК ШУТКА

затем:

ОДИН ИЗ САМЫХ
УЗНАВАЕМЫХ

То есть текст должен следовать РЕЧИ.

НЕ показывать случайные summary words.

НЕ заменять всю фразу одним коротким заголовком.

==================================================
2. СУБТИТРЫ ДОЛЖНЫ БЫТЬ БОЛЬШИМИ
==================================================

Вернуть крупный premium kinetic subtitle style.

Не микротекст.

Не маленькие подписи.

Не обычные YouTube captions.

Размер должен быть достаточно большим, чтобы текст легко читался на 1080p.

Основной текст:

примерно 55–90 px относительно 1920x1080 canvas.

Ключевое слово:

примерно 90–150 px.

Но размер должен адаптироваться к длине текста.

Не делать огромный текст, который закрывает весь экран.

==================================================
3. СУБТИТРЫ ДОЛЖНЫ ПОЯВЛЯТЬСЯ ДИНАМИЧЕСКИ
==================================================

Использовать разные animation presets:

WORD_POP
WORD_SLIDE
WORD_SCALE
WORD_MASK_REVEAL
WORD_RISE
WORD_DROP
WORD_PUNCH
WORD_TRACK
WORD_FLY_IN
WORD_STAGGER
PHRASE_REVEAL
PHRASE_WIPE

Но:

НЕ random.

Animation должен зависеть от смысла.

Например:

"вырос"
→ scale up / rise

"рухнул"
→ drop / downward motion

"резко"
→ punch / impact

"огромный"
→ scale

"появился"
→ reveal

"исчез"
→ fade / shrink

"сравним"
→ split / two-side entrance

==================================================
4. КЛЮЧЕВЫЕ СЛОВА ДОЛЖНЫ ИМЕТЬ ОСОБЫЙ ВЕС
==================================================

Semantic Director должен выделять:

KEY WORD
KEY NUMBER
KEY DATE
KEY COIN
KEY EVENT
KEY RESULT
KEY RISK

Например:

"Dogecoin вырос на 127 процентов."

На экране:

DOGECOIN ВЫРОС

127%

Причём:

DOGECOIN
→ logo / text interaction

ВЫРОС
→ kinetic punch

127%
→ giant animated number

chart
→ одновременно движется вверх.

Это должно происходить одновременно.

==================================================
5. СУБТИТРЫ ДОЛЖНЫ РАБОТАТЬ ВМЕСТЕ С ВИЗУАЛОМ
==================================================

Это самое главное.

Не делать:

VISUAL
+
отдельно subtitles снизу.

Нужно:

VISUAL
+
TEXT
+
DATA
+
MOTION

как единый composition.

Пример:

На экране архивное фото.

Диктор говорит:

"Dogecoin начал набирать популярность."

На фото:

НАБИРАТЬ
→ появляется крупно

ПОПУЛЯРНОСТЬ
→ появляется ещё крупнее

Вокруг:
social/community nodes начинают появляться.

Следующий кадр:

community network
→ текст morphs into chart.

==================================================
6. СУБТИТРЫ НЕ ДОЛЖНЫ ВСЕГДА БЫТЬ ВНИЗУ
==================================================

Это сейчас одна из главных проблем.

Текст должен уметь находиться:

CENTER
CENTER LEFT
CENTER RIGHT
TOP
BOTTOM
LOWER LEFT
LOWER RIGHT

В зависимости от composition.

Если главное изображение находится справа:

subtitle слева.

Если chart занимает центр:

subtitle сверху.

Если fullscreen photo:

subtitle на свободной затемнённой области.

Если HERO MOMENT:

subtitle может быть практически fullscreen.

==================================================
7. OBJECT-AWARE SUBTITLE ENGINE
==================================================

Перед размещением subtitle определить:

MAIN OBJECT
CHART BOUNDS
PHOTO BOUNDS
LOGO BOUNDS
DATA BOUNDS
UI BOUNDS
SAFE ZONES

После этого выбирать оптимальное положение текста.

Никогда не закрывать:

лицо
главный logo
важную цифру
главную часть chart
ключевой объект фотографии.

==================================================
8. НУЖНА РАЗНИЦА МЕЖДУ SUBTITLE И HEADLINE
==================================================

Система должна различать:

SUBTITLE
HEADLINE
LABEL
DATA
CAPTION
SOURCE

Сейчас они местами смешаны.

Правила:

SUBTITLE:
синхронизирован с речью.

HEADLINE:
крупный самостоятельный визуальный statement.

LABEL:
маленькая техническая подпись.

DATA:
цифра / percentage / market cap.

SOURCE:
маленькая строка источника.

Например:

"Dogecoin появился в 2013 году"

SUBTITLE:
DOGECOIN ПОЯВИЛСЯ

DATA:
2013

LABEL:
GENESIS

SOURCE:
verified source

Это разные визуальные уровни.

==================================================
9. ДОБАВИТЬ WORD-LEVEL SYNCHRONIZATION
==================================================

Использовать существующий voice alignment.

Каждое слово должно иметь:

start
end

Не показывать всю subtitle phrase одним блоком на протяжении всей фразы.

Использовать:

word-by-word
phrase-by-phrase
key-word punch

в зависимости от важности.

Не нужно анимировать каждую букву постоянно.

Нужно ощущение профессионального kinetic typography.

==================================================

==================================================

Очень важно.

Мы НЕ хотим:

random text
+
random glow
+
random chart
+
random particles
+
random zoom
+
random sound

одновременно.

Нужен visual hierarchy:

1. MAIN VISUAL
2. KEY DATA
3. KINETIC SUBTITLE
4. SECONDARY DETAIL
5. SOURCE

Главный объект всегда остаётся главным.

12. ДОБАВИТЬ ЕЩЁ НЕМНОГО ВИЗУАЛЬНОЙ ЖИЗНИ

Без изменения общего стиля добавить умеренно:

- chart drawing
- number count-up
- data morphing
- logo morphing

Но только там, где это помогает рассказу.

==================================================
13. VISUAL MORPHING
==================================================

Это особенно важно.

Попробовать сделать несколько красивых переходов:

PHOTO
→ TEXT

TEXT
→ NUMBER

NUMBER
→ CHART

CHART
→ LOGO

LOGO
→ COMPARISON

COMPARISON
→ PHOTO

Например:

"2013"

огромная цифра

2013
↓
zoom
↓
historical photo
↓
photo becomes documentary scene.

Это намного дороже выглядит, чем обычный cut.

==================================================
14. HERO MOMENTS
==================================================

В 45–60 секундном тесте сделать 1–2 действительно сильных HERO MOMENTS.

Не больше.

Например:

HERO:

DOGE logo
+
огромный number
+
chart
+
kinetic text
+
camera push
+
impact sound

И второй:

реальный архивный материал
→ headline
→ timeline
→ transition в market data.

Остальное видео должно быть спокойнее.

==================================================
15. SOUND DESIGN
==================================================

Сохранить существующий sound design.

Но синхронизировать его с:

- subtitle punch
- key word
- number reveal
- chart movement
- logo reveal
- transition
- hero moment

Пример:

KEY WORD appears
→ subtle whoosh

NUMBER hits
→ impact

chart rises
→ subtle rising sound

НЕ делать громкие SFX на каждом слове.

==================================================

Сохранить текущую premium palette:

dark

Typography:

modern

RED:

==================================================
17. УБРАТЬ ВИЗУАЛЬНЫЙ "UI LABEL OVERLOAD"
==================================================

Технические подписи вроде:

MEASURED RISE
MEASURED DRAWDOWN
PRICE AT A FIXED MOMENT
SAME SEVEN DAY WINDOW

можно оставить как secondary labels,

НО они не должны заменять субтитры.

Их количество сократить.

Они должны быть вторичным editorial layer.

Главным текстом должен оставаться реальный смысл диктора.

==================================================
18. САМОЕ ВАЖНОЕ — СЛУШАТЬ СЦЕНАРИЙ
==================================================

Visual Director должен понимать:

ЧТО СЕЙЧАС ГОВОРИТ ДИКТОР.

А не просто:

"сейчас у нас chart scene".

Например:

Диктор:
"Но уже через несколько лет Dogecoin оказался в центре внимания."

Нужно:

ARCHIVE / MEDIA / DOGE VISUAL
+
"В ЦЕНТРЕ ВНИМАНИЯ"
+
headline-style animation
+
camera movement.

А не:

generic chart.

==================================================
19. ФИНАЛЬНЫЙ VISUAL HIERARCHY
==================================================

Каждая сцена должна проходить проверку:

ВОПРОС 1:
Что сейчас главное?

ВОПРОС 2:
Что говорит диктор?

ВОПРОС 3:
Какой визуал это лучше всего показывает?

ВОПРОС 4:
Какой текст нужно показать?

ВОПРОС 5:
Какое слово является ключевым?

ВОПРОС 6:
Какой motion усиливает смысл?

ВОПРОС 7:
Как перейти в следующую сцену?

Если renderer не может ответить на эти вопросы,
он не должен добавлять random effect.
