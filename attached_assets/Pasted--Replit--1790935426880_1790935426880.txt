# LONG VIDEO GENERATION PIPELINE

Для каждого нового LONG-видео строго соблюдать следующий процесс.

ЭТАП 1 — SCRIPT ANALYSIS

Разделить сценарий на смысловые блоки.

Не делить механически по предложениям.

Определять изменение мысли, причинно-следственные связи,
цифры, кульминации и переходы.


ЭТАП 2 — SCENE MAP

Для каждого смыслового блока определить:

— продолжительность;
— главный тезис;
— визуальную метафору;
— главный объект;
— второстепенные объекты;
— тип движения;
— переход в следующую сцену.


ЭТАП 3 — STORYBOARD

Для каждой сцены создать 5–8 последовательных
визуальных событий.

Не писать production-код до завершения storyboard.


ЭТАП 4 — VISUAL DESIGN

Применить:

MOTION_DESIGN_SYSTEM.md

Проверить:
— композицию;
— глубину;
— visual hierarchy;
— количество деталей;
— цвета;
— типографику.


ЭТАП 5 — MOTION DESIGN

Определить:

— entrance;
— build;
— interaction;
— micro-animation;
— exit;
— transition.


ЭТАП 6 — IMPLEMENTATION

Только после предыдущих этапов писать код.


ЭТАП 7 — QUALITY CONTROL

Проверить каждую сцену согласно QUALITY GATE
из MOTION_DESIGN_SYSTEM.md.


ЭТАП 8 — CONTINUITY CHECK

Просмотреть минимум:

предыдущая сцена
+
текущая сцена
+
следующая сцена.

Проверить визуальную непрерывность.


ЭТАП 9 — FINAL RENDER

Только после прохождения всех проверок создавать
финальный render.

Самый надёжный принцип здесь такой: не пытаться заставить Replit «запомнить промпт навсегда». Нужно сделать так, чтобы ему вообще не требовалось его помнить — промпт, правила, палитра, motion-параметры, компоненты и pipeline физически лежат внутри Master-проекта.
Тогда каждый новый LONG создаётся из одного и того же движка, а меняется только сценарий. Это намного стабильнее.
