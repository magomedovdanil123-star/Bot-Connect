==================================================
3. DATA SOURCES
==================================================

Нужно использовать реальные blockchain/on-chain данные.

Приоритетно исследуй интеграцию:

1. Nansen API
2. Whale Alert API
3. Alchemy / аналогичный blockchain data provider
4. Другой надёжный источник при необходимости

Но НЕ подключай всё подряд.

Сначала определи, какой источник лучше подходит для каждого типа события.

Нужно разделить:

A) SMART MONEY / WHALE TRADE

Например:

BUY
SELL
DEX TRADE
ACCUMULATION

B) LARGE TRANSFER

Например:

WALLET → EXCHANGE
EXCHANGE → WALLET
WALLET → WALLET

ВАЖНО:

TRANSFER ≠ SELL.

Если кошелёк отправил ETH на Binance, нельзя автоматически писать:

"Кит продал ETH."

Можно написать:

"Крупный кошелёк перевёл ETH на Binance."

И отдельно:

"Это может быть подготовкой к продаже, но сам перевод не подтверждает продажу."

Точно так же:

TRANSFER ≠ BUY.

Никаких выдуманных интерпретаций.

==================================================
6. WHALE SCORE
==================================================

Создай scoring engine.

Каждому событию присваивать:

WHALE SCORE: 0–100

Score может учитывать:

- размер сделки;
- размер относительно средней сделки;
- редкость события;
- тип кошелька;
- Smart Money label;
- повторные покупки;
- повторные продажи;
- accumulation;
- distribution;
- движение на биржу;
- движение с биржи;
- изменение цены актива;
- объём рынка;
- необычность транзакции;
- предыдущую активность кошелька;
- количество последовательных операций;
- значимость актива.

Пример:

WHALE SCORE
92/100 🔥

Но:

НЕ ПРИДУМЫВАТЬ score из воздуха.

Сохранять breakdown:

{
  size_score,
  smart_money_score,
  unusual_activity_score,
  accumulation_score,
  market_context_score,
  wallet_history_score
}

==================================================
7. НЕ ДЕЛАТЬ SHORT НА КАЖДУЮ ТРАНЗАКЦИЮ
==================================================

Это критически важно.

Система должна отфильтровывать мусор.

Например:

WHALE SCORE < 60
→ ignore

60–74
→ low priority

75–89
→ interesting

90–100
→ BREAKING WHALE EVENT

Порог должен быть configurable.

Создай настройки:

WHALE_MIN_SCORE

WHALE_MIN_USD_VALUE

WHALE_SUPPORTED_CHAINS

WHALE_SUPPORTED_ASSETS

WHALE_MAX_EVENTS_PER_HOUR

WHALE_COOLDOWN

Не хардкодить всё навсегда.

==================================================
8. DUPLICATE PROTECTION
==================================================

Один blockchain event не должен превращаться в 5 одинаковых Shorts.

Создай:

event_id
transaction_hash
deduplication_key

Если несколько providers сообщили одну транзакцию:

→ объединить данные.

Например:

Nansen + Whale Alert
→ один event.

Не:

Nansen event
+
Whale Alert event
=
два ролика.

9. WHALE STORY ENGINE
==================================================

Очень важно.

Мы не просто показываем транзакцию.

Мы строим мини-историю.

Пример:

FACT:

🐋 Smart Money wallet bought
5,240 ETH

VALUE:

$18.4M

PRICE:

$3,511 / ETH

CONTEXT:

ETH had fallen 7.2% over 24h.

HISTORY:

The same wallet previously bought:
$8.2M
$4.7M

TOTAL ACCUMULATION:

$31.3M

INTERPRETATION:

"The wallet appears to be accumulating ETH."

Но только если данные действительно подтверждают несколько покупок.

Разделять:

FACTS

и

INTERPRETATION.

Никогда не выдавать предположение за факт.
